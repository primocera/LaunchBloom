ROLE AND OBJECTIVE
Polish user-facing failure and recovery states across account plan verification, checkout, generation, export, and workspace loading. Errors must preserve trust, avoid false downgrade, and provide one clear next action.
CONTENT PRINCIPLES
State what happened in plain language, what did not happen, and the next safe action.
Never show raw Stripe/Supabase/AI provider text, stack traces, internal IDs, or blame the user.
Avoid false certainty: generation output still needs review; SEO Ideas require actual research; Social Calendar plans but does not publish.
Do not use 'production-ready', 'send-ready', 'ready to paste', or imply automatic publishing/compliance.
REQUIRED STATES
Plan verification unavailable: preserve access state and offer retry/support.
Checkout configuration unavailable: confirm no charge, allow retry later, never silently switch currency.
Generation timeout/provider failure: preserve brief/input, avoid double usage charge, offer retry.
Usage limit reached: show allowance/reset/upgrade facts without pressure dark patterns.
Export failure: keep reviewed assets and provide retry/download alternative if available.
Empty/new workspace: guide Brand Profile → Campaign Brief → first reviewed asset, not a wall of five disconnected generators.
IMPLEMENTATION REQUIREMENTS
Create a small typed error-to-copy mapping rather than duplicated strings.
Add accessible alerts, focus management, loading-state semantics, disabled-button reasons, and keyboard recovery paths.
Instrument error category and recovery action without storing campaign content.
Write UI tests for exact state and action, not brittle full-page snapshots.
ACCEPTANCE CRITERIA
Every critical error answers: what happened, was I charged/did I lose work, and what can I do now?
No temporary plan error renders Free.
No deceptive readiness/publishing claim returns.
FINAL REPORT
Return: (1) exact files changed, (2) behavior before and after, (3) tests run with exact pass/fail counts, (4) commands not run and why, (5) residual risks, (6) documentation/evidence updated, and (7) whether the next prompt is safe to start.
Use PASS only for a command or production observation that actually ran against the stated commit and environment. Use BLOCKED, NOT RUN, or FAILED otherwise.
Do not claim launch readiness in prose. Report evidence; the repository's release gate and the owner determine the verdict.
