# SC-P0-04 · Production launch configuration must fail closed

PriorityDepends on

PASTE INTO CLAUDE CODE
ROLE AND OBJECTIVE
Make production launch configuration fail closed by default. ENFORCE_LAUNCH_CONFIG must not be an optional safety switch that can accidentally remain off in a paid production deployment.
IMPLEMENTATION REQUIREMENTS
Inventory all launch-critical configuration: Stripe keys/webhook secret, current and regional price IDs, application URL, legal URLs, support/contact address, Supabase credentials, origin/CORS settings, rate-limit/storage dependencies, and any trial/billing feature flags.
In production, enforce critical validation automatically. Allow an explicit bypass only in tests or non-production development. Name it as unsafe and reject it when NODE_ENV=production.
Run validation at application startup or deployment/build check where failure is visible before serving paid checkout. Also retain request-time defense in depth.
Reject placeholder domains, localhost return URLs, missing terms/privacy links, inactive/foreign Stripe products, and incomplete enabled currency catalogs.
Keep secret values out of errors. Report only the missing/invalid variable name and safe remediation category.
Update env examples, deployment documentation, release-check scripts, and tests. Document exact behavior by environment.
TESTS
Production with missing legal URL fails.
Production with missing required Stripe mapping fails.
Production with unsafe bypass set fails.
Development/test remains usable with documented stubs.
Valid production-shaped config passes without printing secrets.
Run full lint/test/build/fresh bundle gates.
ACCEPTANCE CRITERIA
A production paid checkout route cannot serve when critical configuration is invalid.
The safe default does not depend on remembering a flag.
Error output is actionable and secret-safe.
FINAL REPORT
Return: (1) exact files changed, (2) behavior before and after, (3) tests run with exact pass/fail counts, (4) commands not run and why, (5) residual risks, (6) documentation/evidence updated, and (7) whether the next prompt is safe to start.
Use PASS only for a command or production observation that actually ran against the stated commit and environment. Use BLOCKED, NOT RUN, or FAILED otherwise.
Do not claim launch readiness in prose. Report evidence; the repository's release gate and the owner determine the verdict.
END OF PROMPT
