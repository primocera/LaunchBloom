ROLE AND OBJECTIVE
Define and implement a deterministic canonical entitlement policy for customers with multiple Stripe subscriptions or historical price IDs. The policy must avoid accidental downgrade, preserve security, and generate an operations signal for impossible states.
REQUIRED ANALYSIS
Map every subscription status considered entitling, every known current/retired price mapping, cancellation-at-period-end behavior, and webhook reconciliation path.
Inspect backend/routes/customers.js, backend/routes/payments.js, plan catalog/mapping helpers, webhook handlers, support/admin views, and all related tests.
Write a short decision record before coding. Compare at least: newest mapped row, highest active entitlement, Stripe primary/current subscription, and event-order-based canonical record.
IMPLEMENTATION REQUIREMENTS
Choose one canonical rule and encode it in a single pure resolver reused by all billing surfaces. Prefer a rule that cannot silently downgrade a user when two valid entitling rows coexist.
Separate canonical access from anomaly reporting. A customer may retain the safest valid entitlement while the overlap is flagged for reconciliation.
Make status precedence explicit. Unknown prices, foreign products, incomplete rows, canceled-but-still-entitled periods, and future-dated events must have named outcomes.
Do not grant access from a foreign Stripe product or unverified client metadata. Preserve existing shared-Stripe product isolation.
Emit a redacted structured anomaly event with customer correlation safe for operations. Do not put raw customer email in logs.
Add an idempotent reconciliation function/runbook that can identify overlaps without mutating production by default. Any destructive cleanup must require an explicit owner mode and dry-run output.
TEST MATRIX
Free only; one current active plan; one retired active price; retired plus current active; two current plans at different levels; active plus past_due; cancel_at_period_end within entitlement window; fully expired; unknown price; foreign product; unordered/replayed webhook events; database error.
Property: resolution does not depend on arbitrary database row order.
Property: a lower plan cannot win only because it is newer if the approved policy says highest valid entitlement wins.
Run full tests and build after narrow resolver tests.
ACCEPTANCE CRITERIA
One documented source of truth is used by checkout prevention, account display, usage allowance, and support tooling.
Overlaps are deterministic, tested, and visible to operations; no silent downgrade or cross-product entitlement.
