PASTE INTO CLAUDE CODE
ROLE AND OBJECTIVE
Resolve the production dependency advisories affecting react-router/react-router-dom 6.30.4. Prefer a controlled migration to the currently safe supported release if compatible; otherwise implement and document a time-bounded mitigation with tests and an explicit owner-approved residual risk.
ADVISORY CONTEXT
Review GHSA-jjmj-jmhj-qwj2, GHSA-wrjc-x8rr-h8h6, and GHSA-337j-9hxr-rhxg using primary advisory/package sources.
Do not use npm audit fix --force. Do not assume an advisory is irrelevant without tracing actual route/navigation behavior.
IMPLEMENTATION PLAN
Inventory all routing APIs, loaders/actions, redirects, search-param-derived navigation, auth return paths, marketing links, and error boundaries.
Attempt the smallest supported upgrade path. If moving to React Router 7, read official migration guidance, identify breaking changes, update code and tests intentionally, and keep the UI behavior unchanged.
Centralize safe internal navigation validation for any untrusted redirect/next/returnTo input. Only allow expected same-origin application paths.
Regenerate lockfile deterministically. Record the before/after production audit and explain any remaining advisory.
If upgrade is blocked, implement path validation at every reachable sink, add exploit-oriented tests, pin a remediation owner/date, and keep release verdict conditional. Do not mark the vulnerability closed.
TESTS
All routing/navigation tests; auth redirect tests; malformed and cross-origin redirect payloads; public E2E; full unit tests; lint; build:app; check:app-fresh; npm audit --omit=dev.
If the browser binary is unavailable, record public E2E as BLOCKED and provide the exact prerequisite. Never reuse an old E2E result for the new dependency tree.
ACCEPTANCE CRITERIA
The lockfile uses a patched supported router version, or a documented and tested mitigation remains explicitly open with owner acceptance.
No user-controlled URL can drive external navigation through affected sinks.
No unrelated UI rewrite is introduced.
FINAL REPORT
Return: (1) exact files changed, (2) behavior before and after, (3) tests run with exact pass/fail counts, (4) commands not run and why, (5) residual risks, (6) documentation/evidence updated, and (7) whether the next prompt is safe to start.
Use PASS only for a command or production observation that actually ran against the stated commit and environment. Use BLOCKED, NOT RUN, or FAILED otherwise.
Do not claim launch readiness in prose. Report evidence; the repository's release gate and the owner determine the verdict.
