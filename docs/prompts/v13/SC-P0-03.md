ROLE AND OBJECTIVE
Harden regional pricing so Scalvya never displays EUR and silently opens a USD/Adaptive Currency checkout. If the configured regional price cannot be created, fail clearly and safely instead of retrying in another currency.
FILES AND FLOWS TO TRACE
backend/lib/currency.js
backend/lib/plan-catalog.js
backend/routes/payments.js
backend/routes/plans.js
frontend pricing/paywall/account checkout components
verify-prices and launch-config scripts/tests
IMPLEMENTATION REQUIREMENTS
Remove the generic catch-and-retry behavior that detects a StripeInvalidRequest message containing currency/usd/eur and silently retries without the requested currency.
Use an explicit server-side catalog selection result: country/region, selected currency, selected plan price ID, catalog version, and availability. Never let client input select arbitrary price IDs.
When EUR is enabled for an eligible region, require all intended EUR prices to pass configuration verification before the feature can be enabled in production. If incomplete, keep the region on the explicitly configured fallback catalog before display, or return a stable configuration error; never change currency after the user saw the price.
Return a human-safe checkout error: 'Checkout is temporarily unavailable for this price. You have not been charged.' Include retry/support guidance, not raw Stripe text.
Record the selected catalog currency and price key in redacted structured telemetry so support can correlate a mismatch without PII.
Ensure pricing page, paywall, checkout CTA, and server-created Checkout Session all use the same authoritative catalog version.
Update verify-prices to prove every required plan/currency pair, product ownership, active status, recurring interval, amount, and currency. A missing pair must be a hard failure when EUR launch is enabled.
TESTS
EU/EEA eligible country with complete EUR catalog creates EUR checkout.
EU/EEA with missing EUR price does not display EUR and later charge USD; assert no Stripe session is created after an already displayed EUR offer.
Non-EU region uses the intended USD catalog.
Tampered client price/currency is ignored or rejected.
Stripe typed invalid-request/config errors map to stable public errors without message-string parsing.
Run verify-prices only in read-only mode when credentials are available; otherwise mark BLOCKED and include the exact owner command.
ACCEPTANCE CRITERIA
For every successful checkout, displayed and charged amount/currency originate from the same server catalog selection.
No silent cross-currency retry remains.
Production EUR enablement is impossible with an incomplete catalog.
NON-GOALS
Do not perform live charges or create/modify Stripe prices without owner approval.
Do not invent tax/VAT compliance claims.

Use PASS only for a command or production observation that actually ran against the stated commit and environment. Use BLOCKED, NOT RUN, or FAILED otherwise.
Do not claim launch readiness in prose. Report evidence; the repository's release gate and the owner determine the verdict.
