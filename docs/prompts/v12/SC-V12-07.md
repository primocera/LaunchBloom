# SC-V12-07 · Scalvya — Add scale-safe limits, isolation and operational observability

**Run after:** SC-V12-06.
**Primary risk removed:** a small beta can absorb manual intervention; paid scale cannot absorb
shared-account event leakage, invisible spend growth or fail-open cohort controls.

## Prompt

Harden Scalvya for controlled growth without adding new customer-facing features.

Inspect and improve:
1. Shared Stripe isolation: allowlist Scalvya product and price IDs; ignore foreign Mellowa
   events with no mutation or email; test both directions using realistic payload fixtures.
2. AI spend control: distinguish alert threshold from hard brake; ensure reservation and
   generation stop safely at the configured daily ceiling; failed generations must release
   reservations correctly; expose aggregate operational counters without PII.
3. Cohort control: a configured capped beta must fail closed if its cap configuration is missing
   or invalid; document the deliberate behavior for open public signup; add a tested emergency
   signup stop and AI generation kill switch.
4. Operational readiness endpoint: report presence/health only, never secret values; include
   webhook failures, outbox backlog, AI spend, reservation leakage, export failures and ignored
   foreign Stripe events; define warning and stop thresholds.
5. Email: optional mail respects suppression; transactional billing/security mail still sends;
   cross-product events can never produce mail.
6. Incident runbook: add first-response actions, rollback switches, data to inspect, owner and
   escalation threshold for billing, AI spend, email, auth and export incidents.

Acceptance:
- No new analytics event may include campaign copy, prompts, email addresses or customer content.
- Every fail-open/fail-closed decision is explicit and tested.
- All changes remain additive and reversible.
- Run focused isolation/spend/email/readiness tests, full unit suite and production build.
