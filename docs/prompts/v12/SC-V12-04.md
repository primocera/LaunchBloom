# SC-V12-04 · Scalvya — Prove billing recovery and webhook ordering before scale

**Run after:** SC-V12-03.
**Primary risk removed:** a late payment_failed event after recovery may remove access from a
paying user; the complete live state transition has not been rehearsed.

## Prompt

Strengthen Scalvya billing correctness and prepare an owner-run live rehearsal. Do not perform a
real charge, refund or production mutation yourself.

Inspect:
- Stripe webhook routing and event allowlists
- subscription/entitlement reconciliation
- event idempotency storage
- checkout, portal and cancellation flows
- cross-app isolation for the shared Stripe account
- docs/RUNBOOK_TRANSACTION_REHEARSAL.md and owner evidence schema

Required code-level work:
1. Define the canonical subscription state machine and the source of truth for entitlement.
2. Add deterministic tests for duplicates, retries and out-of-order events, including:
   checkout/session completion; trialing -> active; cancel at period end; reactivate;
   invoice.payment_failed; recovery/payment_succeeded; a late payment_failed arriving after
   recovery; refund; dispute; foreign Mellowa product/price/customer events; repeated delivery of
   every relevant event.
3. Entitlement must reconcile to Stripe's canonical current state rather than blindly applying
   event arrival order.
4. Foreign products and prices must be acknowledged safely but produce no Scalvya data mutation,
   email or failure alert.
5. Verify an event cannot trigger duplicate generation credits, duplicate email or duplicate
   entitlement changes.
6. Add structured operational signals for webhook failures, ignored foreign events and
   reconciliation corrections without exposing PII.

Owner-run rehearsal document:
- Use a real low-value Scalvya plan only after the owner intentionally starts the run.
- Include preconditions, abort conditions, exact expected Stripe state, expected app entitlement,
  expected email, evidence field and cleanup for every transition.
- Include charge -> cancel -> reactivate -> failed payment -> recovery -> deliberately late
  failure -> refund.
- State which steps cost money and which require owner confirmation.
- Never place secrets, full customer identifiers or card data in evidence.

Release rule:
- Unit/contract tests do not close the live-money owner-evidence item.
- Until all required live rows have observed evidence, public paid may be at most CONDITIONAL GO.

Run all billing, webhook, email and release-manifest tests and report the exact residual live
risk.
