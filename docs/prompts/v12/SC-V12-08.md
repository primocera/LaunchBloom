# SC-V12-08 · Scalvya — Cut the new candidate and issue an honest final verdict

**Run after:** SC-V12-01 through SC-V12-07 merged.
**Primary risk removed:** evidence from the old frozen candidate can be incorrectly reused after
product-code changes.

## Prompt

Cut a new Scalvya release candidate only after every intended v12 code change is merged. This is
a release-evidence task, not a feature task.

Procedure:
1. Confirm the working tree is clean and record the exact current HEAD.
2. Review the diff from the previous frozen candidate and classify every changed file as product
   code, test, generated bundle, evidence or documentation.
3. Rebuild the production frontend and verify app/ matches app-src/ exactly.
4. Run every required automated gate at the same candidate SHA: lint; complete
   unit/contract/safety suite; production build; stale-bundle check; public browser suite at
   every configured viewport; authenticated matrix; export integrity; launch-state integrity;
   release configuration check in its authorized environment.
5. Record raw outputs with exact counts. No required skip may be called a pass.
6. Reconcile migrations using observed production evidence supplied by the owner. Presence on
   disk is not applied-state evidence.
7. Reconcile owner-only evidence: live billing rehearsal; email suppression; production
   configuration; AI spend controls.
8. Set candidate SHA only after all code is frozen. Evidence-writing commits may be
   documentation-only; any later product-code commit creates a new candidate.
9. Generate the canonical launch document from the manifest.
10. Compute verdicts:
    - GO only with complete required evidence and no accepted/open P0/P1.
    - CONDITIONAL GO when every unaccepted blocker is closed but accepted required risk remains.
    - NO-GO for any unsatisfied unaccepted requirement, stale evidence or code drift.

Do not upgrade a verdict to satisfy a desired launch date. Finish with separate verdicts for
capped beta and unrestricted public paid, the exact reasons, remaining owner actions and rollback
triggers.
