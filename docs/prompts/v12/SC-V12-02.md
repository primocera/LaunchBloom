# SC-V12-02 · Scalvya — Fix hero readability while preserving the approved blue

**Run after:** SC-V12-01.
**Primary risk removed:** white helper text and proof content falls as low as ~1.99:1 contrast in
the current hero text band.

## Prompt

You are working in primocera/LaunchBloom after SC-V12-01. Fix the real hero contrast defect with
the smallest visually faithful change.

Verified starting point:
- The live hero uses the approved saturated blue-to-white sky treatment.
- A previous navy scrim was rejected because it dulled the blue.
- Opaque/glass surfaces behind the helper text and proof strip were rejected.
- The current lower text band does not meet WCAG AA; the existing test records the failure floor
  and can pass while the page remains inaccessible.

Design constraints:
- Keep the approved top blue token unchanged.
- Do not add a hero-wide black/navy scrim.
- Do not add opaque or glass-card backgrounds to the CTA note.
- Keep the existing open-sky visual character, meteor/cloud decoration and section transition.
- Preserve layout and mobile behavior unless a measured issue requires a change.

Preferred solution to implement and visually validate:
1. Keep the saturated blue through the complete area in which white hero copy, CTA disclosure and
   proof-strip text can render.
2. Delay the fade toward pale blue/white until below the text band.
3. Use gradient stops whose interpolated background maintains at least 4.5:1 against opaque white
   throughout the measured text band.
4. If this causes an abrupt lower transition, adjust only the post-content transition stops or sky
   height. Do not solve it with a scrim.
5. Shorten the hero supporting paragraph without changing the canonical promise or boundaries:
   - lead with freelance marketers and boutique agencies;
   - keep solo founders as a secondary use case;
   - keep the meaning of launch-ready;
   - keep publishing responsibility and trial disclosure explicit;
   - do not invent performance or customer claims.

Test changes:
- Replace the "known shortfall must remain below AA" assertion with a real WCAG AA requirement.
- Parse the actual gradient and sample the complete defined text band at small intervals.
- Assert every sample is >= 4.5:1 for normal white text.
- Assert the approved top blue token is unchanged.
- Assert no hero scrim or new helper/proof glass surface exists.
- Keep focus-visible, reduced-motion and ghost-button checks.
- Add/adjust browser assertions at desktop, 375px and 320px so the proof strip remains readable
  and does not overflow.

Documentation:
- Update the UX defect ledger to describe this as fixed in the new candidate, but explicitly state
  that the previous frozen candidate still carried the accepted risk.
- Do not close the canonical release blocker until the new candidate is cut and the new tests are
  recorded at that SHA.

Validation:
- Run the focused contrast tests first, then content-contract tests, then public browser tests at
  all configured viewports. Build the production frontend and verify the committed bundle is
  fresh. Provide before/after measured minimum contrast; screenshots only if the repository
  workflow already captures them.
