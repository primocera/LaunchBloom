# SC-V12-03 · Scalvya — Make authenticated E2E impossible to skip silently

**Run after:** SC-V12-02.
**Primary risk removed:** the signed-in matrix exists but has not proven mobile, keyboard,
cross-account isolation and failure paths at the current candidate.

## Prompt

Harden and execute the authenticated Scalvya browser matrix against an explicitly non-production
environment. Do not point any seed or destructive test at production.

Inspect first:
- docs/RUNBOOK_AUTH_E2E.md
- scripts/e2e-auth.mjs
- e2e/authenticated/**
- backend/migrations/E2E_MARKER.sql
- seed routes and all guard tests
- CI/release workflow behavior when environment variables are missing

Required behavior:
1. The runner must distinguish PASS, FAIL and BLOCKED. Missing environment or missing
   non-production marker must exit non-zero with BLOCKED, never exit zero as skipped.
2. Require all existing process-level guards plus a database-level marker that cannot be simulated
   by a local environment variable.
3. Refuse known production URLs/project references and document how the refusal is determined
   without printing secrets.
4. Make fixtures deterministic, isolated per run and automatically cleaned up where safe.
5. Ensure one account can never read or mutate another account's brand, campaign, asset, review or
   export data.
6. Cover desktop, phone and keyboard-only projects.
7. Cover at least: signup/login and initial activation; Brand Profile completion; Campaign Brief
   creation/edit; each of the five Create paths; generation success and provider failure; Review
   findings and status transition; Library/version/provenance; export preview and reload during
   export; session expiry; cross-account isolation; mobile navigation and Sign out.
8. Every required journey must execute. A suite with any required skip must fail the
   release-candidate gate.
9. Capture raw machine-readable evidence with candidate SHA, environment class, project names,
   counts and timestamps, without secret values or user data.

CI rules:
- Ordinary pull requests without secrets may report the authenticated job as visibly
  BLOCKED/SKIPPED, but that job is never launch evidence.
- When RC_GATE=1 or equivalent release mode is enabled, missing configuration or any skip is a
  hard failure.
- Do not seed production.

Finish only after reporting exact executed/pass/fail/skip counts. If the required non-production
environment is unavailable, improve the harness and tests, leave the launch item unresolved and
provide the exact owner command sequence needed to run it.
